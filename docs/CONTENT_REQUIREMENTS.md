> 목적: 추가하기로 한 **10종 컨텐츠**의 동작 요구사항(design spec)을 확정하고, 구현 착수 전 결정해야 할 미결 사항을 정리한다.

## 1. 공통 개념 5

각 컨텐츠 요구사항이 반복 참조하는 기반 개념. **먼저 확정하면 개별 명세가 짧아진다.**

| 개념 | 정의 | 사용하는 컨텐츠 |
|------|------|-----------------|
| **즉사 접촉** | 접촉 순간 플레이어 사망(예외 없음). 현재 스파이크와 동일 규칙 재사용. | 진자추, 튀는가시, 낙하함정, 압사기, 화살, 발사체 |
| **예고(Telegraph)** | 위험 발동 직전 신호(시각/청각)로 회피 기회를 주어 공정성 확보. | 튀는가시, 낙하함정, 압사기, 조준형 터렛 |
| **상태 사이클** | `대기 → 발동 → 복귀`를 반복하는 시한/주기 동작. 결정론적이어야 테스트·리셋 용이. | 튀는가시, 낙하함정, 압사기, 화살, 터렛 |
| **운반(Carry)** | 발판이 그 위에 선 플레이어를 함께 이동시킴. Arcade Physics에서 가장 까다로운 부분. | 이동발판, 컨베이어 |
| **발사체(Projectile)** | `스폰 → 직선 이동 → 소멸`. 여러 발생원이 공유하는 재사용 자원(풀). | 화살, 터렛 |

## 2. 컨텐츠별 요구사항

### 그룹 A — 발판/이동계

#### A-1. 점프대(스프링)
- **정의:** 위에서 밟으면 일반 점프보다 훨씬 높게 강제 반발.
- **동작:** 대기 → 밟힘(눌림 애니, 매우 짧게) → 즉시 상향 속도 부여. 자체 쿨다운 없음(튕겨 나가면 자동 해제).
- **상호작용:** **위 접촉만** 반발. 옆/아래 접촉은 일반 발판처럼 막힘. 반발 중에도 좌우 조작 유지.
- **파라미터:** 반발 세기(예: 일반 점프의 1.6~2.0배 높이), 눌림 애니 시간.
- **필수 규칙:** 반발 속도는 **variable jump cut(점프 버튼 떼면 짧아짐)의 예외**여야 한다. 아니면 스프링을 밟고 버튼을 안 누른 상태라 즉시 반감됨.

#### A-2. 이동 발판
- **정의:** 정해진 경로를 왕복/순환하는 발판. 위에 타면 함께 이동(**운반**).
- **동작:** 상시 이동, 끝점에서 반전. (선택) 끝점 대기시간, 발판 간 위상차.
- **상호작용:** 위에 선 플레이어를 미끄러짐 없이 운반. 옆에서 밀면 막힘.
- **파라미터:** 축(수평/수직), 이동 범위 또는 두 끝점, 속도, 끝점 대기시간, 시작 위상.
- **까다로운 요구(운반):**
  - 수평: 발판 속도만큼 플레이어가 따라와야 함(미끄럼 방지).
  - 수직 상승: 밀어 올리되 압착 사망 방지. 수직 하강: 플레이어가 발판보다 느리게 떨어져 **떠버리는 현상** 방지(붙어있게).
  - 발판이 플레이어를 천장/벽에 **압착**할 때 처리(즉사 또는 밀어내기) 정의 필요.

#### A-3. 컨베이어 벨트
- **정의:** 위에 접지 중이면 한 방향으로 지속적으로 밀리는 발판.
- **동작:** 방향 고정 상시 작동.
- **상호작용:** 접지 중 플레이어 수평 속도에 벨트 속도 **가산**. 역방향으로 걸으면 느려지고 순방향이면 빨라짐. **가만히 있으면 벨트 끝으로 밀려남**(구덩이/가시로 미는 함정용).
- **파라미터:** 방향(좌/우), 벨트 속도.
- **필수 규칙:** 공중(점프 중)에는 무효.

### 그룹 B — 상시 위험

#### B-1. 진자 가시 추
- **정의:** 고정점에 매달려 좌우로 흔들리는 가시 추. 헤드에 닿으면 **즉사**.
- **동작:** 상시 진자 운동(양 끝에서 느려지고 중앙에서 빠름 = sin 기반). 결정론적.
- **상호작용:** 헤드(가시) 접촉 시 즉사. 사슬 부분은 무해(기본).
- **파라미터:** 고정점 좌표, 사슬 길이, 진폭(각도), 주기, 위상.
- **활용:** 여러 개를 위상 다르게 배치 → 리듬 통과 퍼즐. 양 끝의 감속이 통과 창을 만든다.

### 그룹 C — 숨은 함정

#### C-1. 위장 발판(가짜 바닥)
- **정의:** 진짜처럼 보이나 지지하지 못하는 발판.
- **변형 2종:** (a) **완전 가짜** — 밟는 즉시 통과해 추락. (b) **밟으면 꺼짐** — 잠깐 버티다 사라짐.
- **상호작용:** 지지 실패 → 추락(구덩이 사망 규칙 재사용).
- **파라미터:** 꺼짐 지연(0=즉시 통과), 리스폰 여부.
- **확정 필요:** 진짜와의 **구분 단서 정책**(미세한 색조 차이=관찰 보상 vs 완전 동일=순수 함정).

#### C-2. 튀어나오는 가시
- **정의:** 평소 숨어있다 트리거되면 솟는 가시. 활성 중 접촉 시 **즉사**.
- **동작(상태 사이클):** 숨김 → **예고** → 활성(솟음) → 복귀 → 숨김.
- **트리거(택1 이상):** 주기 타이머 / 근접·압력판 / 위 통과.
- **상호작용:** 활성 상태에서만 즉사. 숨김·예고 중엔 무해.
- **파라미터:** 예고시간, 활성 유지시간, 복귀시간, 주기, 트리거 반경.
- **필수 규칙:** **예고 필수**(없으면 불공정). 주기형=리듬, 트리거형=반응/기억.

#### C-3. 낙하 함정(트랩도어)
- **정의:** 밟으면 잠시 후 열려 빠지는 바닥(위장 + 지연이 핵심).
- **동작:** 닫힘(정상 발판) → 발동(흔들림/삐걱) → 열림(사라짐) → (선택) 복구.
- **트리거:** 플레이어 착지/접촉.
- **상호작용:** 열림 시 지지 안 함 → 추락 사망.
- **파라미터:** 열림 지연(=도망 창; 0이면 즉사로 가혹), 복구 여부/시간.

#### C-4. 압사기(Thwomp)
- **정의:** 대기하다 플레이어가 범위에 들면 빠르게 내리찍고 천천히 복귀.
- **동작(비대칭이 핵심):** 대기 → (감지) → **급강하(빠름)** → 바닥 대기(잠깐) → **복귀(느림)** → 대기.
- **트리거:** 아래 X범위 진입(또는 상시 주기).
- **상호작용:** 낙하 경로/찍는 순간 접촉 시 즉사. **몸통 위·옆은 발판**(위에 탑승 가능 여부는 미결).
- **파라미터:** 감지범위, 낙하속도(빠름), 바닥 대기시간, 복귀속도(느림), 낙하거리.
- **필수 규칙:** 착지 시 화면 흔들림(피드백). "빠른 강하 + 느린 복귀" = 복귀 중 통과 타이밍 퍼즐.

### 그룹 D — 발사계 (발사체 공유)

#### D-1. 화살/다트 발사기
- **정의:** 벽·기둥 고정 발사기. 트리거 시 수평 발사체 발사. 발사체 접촉 시 **즉사**. 본체는 파괴 불가.
- **동작(택1):** (a) **트립와이어** — 보이지 않는 선 통과 시 발사(관찰/기억) (b) **주기 자동**(리듬).
- **파라미터:** 발사 방향, 발사체 속도, 발사 간격/쿨다운, 트립와이어 위치, 사거리.
- **확정 필요:** 발사체가 **지형에 막히는지**(엄폐물 뒤 안전) vs 관통.

#### D-2. 발사체 적 / 터렛
- **정의:** (거의) 고정 적. 주기적/감지 시 발사체를 쏨. **본체는 위에서 밟아 처치 가능**.
- **동작:** 대기/조준 → 발사 → 쿨다운 → 반복.
- **상호작용:** 발사체→플레이어=즉사 / 플레이어가 본체를 위에서 밟으면=처치, 옆 접촉=사망.
- **조준 방식(택1):** 고정 방향 / 플레이어 조준(에임) / 부채꼴 다발.
- **파라미터:** 발사 주기, 발사체 속도, 조준 방식, 감지 범위, 발사 개수.
- **필수 규칙:** 발사 중에도 본체는 밟기 가능(취약 창 보장). 조준형이면 조준 예고 필요.

## 4. ⚠️ 구현 전 확정 필요 (미결정 사항)

> 구현 단계에서 반드시 부딪히는 질문들. **여기서 방향을 못 박아야 뒷단 재작업이 없다.** 위 요구사항만으로는 아직 답이 없는 것들.

### 4-A. 전역 결정 (모든 컨텐츠에 영향)

> **✅ 확정 (2026-07-24)** — G1·G2·G3 결정 완료. G4~G7은 기본값 채택(뒤집을 이유 있을 때만 재검토).
> - **G1 = 원히트 즉사 유지** — 체력 시스템 미도입. 난이도는 배치로 조절.
> - **G2 = 시각 예고만** — 오디오 시스템 미도입. 예고는 점멸·바닥 균열·조준선 등 화면 신호로만.
> - **G3 = 통합 배열 + 선택 `type`/`kind`** — `level1` 무수정 하위호환, 기본값=기존 동작.

| # | 결정 사항 | 왜 지금 정해야 하나 | 결정 / 기본값 |
|---|-----------|--------------------|-------------------|
| **G1** | **피격 모델: 원히트 즉사 vs 체력+무적시간** | 발사체·압사기·가시가 밀집하면 원히트는 극악 난이도. 체력 도입 시 "즉사 접촉" 규칙 전체가 "데미지+무적시간"으로 바뀜 → **모든 즉사 컨텐츠의 근본 규칙이 달라짐.** | ✅ **원히트 즉사 유지**(현재 구조). 배치로 난이도 조절 |
| **G2** | **예고 채널: 사운드 지원 여부** | 현재 오디오 시스템 **전무**. 튀는가시·압사기·트랩도어·조준터렛이 "예고"를 요구하는데, 사운드가 없으면 **전부 시각 예고로만** 설계해야 함. | ✅ **시각 예고만**(점멸·균열·조준선). 사운드는 후속 |
| **G3** | **레벨 데이터 스키마 확장 방식** | 컨텐츠마다 필드 분리 vs `hazards`/`platforms` 통합 배열 + `type`/`kind`. 하위호환(`level1` 무수정) 위해 선택 필드 + 기본값 정책 필요. | ✅ **통합 + 선택 `type`**, 기본값=기존 동작 |
| **G4** | **좌표/크기 단위 규약** | 스파이크는 32px 타일 단위, 발판은 픽셀. 진자 길이·이동발판 범위·압사기 낙하거리 등 신규 수치의 단위를 통일해야 데이터가 안 헷갈림. | 픽셀 기준, 타일 요소만 32px 배수 |
| **G5** | **렌더 순서(depth) 규약** | 발사체·진자추·이동발판·예고 이펙트가 배경/발판/플레이어 앞뒤 어디에 그려질지 현재 규칙이 거의 없음(배경 -10, HUD 1000뿐). 겹침 버그의 근원. | 배경<발판<장애물<적<발사체<플레이어<이펙트<HUD 레이어 상수화 |
| **G6** | **씬 재시작 시 상태 리셋 보장** | 상태머신 컨텐츠(가시/압사기/트랩도어/터렛)는 사망→재시작 때 **초기 상태로 확정 리셋**돼야. 또 `ending` 중(사망 연출) 이들이 계속 움직일지 멈출지 결정 필요. | `create()`에서 항상 초기화, `ending` 중 정지 |
| **G7** | **결정론·테스트 분리** | 진자 위치, 압사기 상태전이, 발사체 궤적, 운반 델타는 순수 함수로 뽑으면 `patrol.test.ts` 선례처럼 테스트 가능. 물리엔진에 맡기면 테스트·리셋이 어려움. | 궤적/상태전이는 순수 함수로 |

### 4-B. 항목별 미결 질문

| 컨텐츠 | 구현 중 나올 질문 | 결정 포인트 |
|--------|-------------------|-------------|
| 점프대 | 반발 후 coyote/jump-buffer 상태를 리셋하나? 스프링 위에서 **연속 바운스** 허용? | 1회 반발 vs 자동 반복 |
| 이동발판 | 운반을 **위치 델타 보정**으로 할지(표준 Arcade 이슈). 발판 위 **적도** 태우나? | 캐리 정책, 탑승 대상 |
| 컨베이어 | 이동발판과 **결합**(움직이는 컨베이어) 허용? 벨트 속도>플레이어 속도면 역주행 불가? | 조합 허용 범위 |
| 진자추 | 고정점 데이터 표현(점+길이+각도범위). 히트박스=헤드만 vs 사슬 포함? | 데이터 형식, 히트박스 |
| 위장발판 | 진짜/가짜 **구분 단서**(위 G와 별개로 확정). 아래에서 점프로 뚫기 허용? 리스폰? | 단서 정책, 통과 방향 |
| 튀는가시 | 트리거 3방식 중 **먼저 구현할 1개**. 그 위에 서 있을 때 발동 처리(즉사/밀어올림)? | 우선 트리거, 상단 접촉 |
| 낙하함정 | **복구 여부**(반복 도전 vs 외길). 로직이 "위장발판 b형"과 사실상 동일 — **통합**할까? | 복구, 컴포넌트 통합 |
| 압사기 | 위에 **탑승 가능**하게 할지(엘리베이터 활용 = 복잡도↑). 낙하 정지=지형 접촉 vs 고정 거리? 감지 vs 주기? | 탑승, 정지 방식, 트리거 |
| 화살 | 트립와이어 vs 주기 중 **먼저 구현**. 발사체 **지형 충돌**(G와 연동). 소멸 조건(화면밖/사거리/벽)? | 우선 방식, 충돌·소멸 |
| 터렛 | 조준 방식 3종 중 **먼저 구현**. **밟기 vs 발사체 동시 접촉** 우선순위? 밟아 죽인 뒤 **잔여 발사체** 유지? | 우선 조준, 판정 우선순위, 잔여 처리 |

## 5. 공용 부품 — 이걸 먼저 만들면 이득

요구사항을 관통해보면 **3개 공용 부품**이 여러 컨텐츠에 재사용된다. 개별 컨텐츠보다 먼저/함께 설계하면 중복 작업이 사라진다.

1. **즉사 접촉 규칙** — 진자·가시·압사·발사체가 전부 공유. **G1=원히트 확정**이므로 현재 스파이크 overlap→`handleDeath` 경로를 그대로 일반화하면 됨.
2. **발사체 풀** — 화살 + 터렛 공유. 소멸·지형충돌 정책(G, 4-B) 여기서 확정.
3. **운반(Carry) 물리** — 이동발판 + 컨베이어 공유. 셋 중 **가장 까다로움**, 순수 함수로 뽑아 테스트 권장(G7).

### 권장 구현 순서(요구사항 관점)
1. ~~G1·G2·G3 확정~~ ✅ 완료 (원히트 / 시각 예고만 / 통합 스키마).
2. **즉사 규칙 일반화** → 진자추(가장 단순한 즉사) 1개로 검증.
3. **운반 부품** → 이동발판 → 컨베이어.
4. **발사체 부품** → 화살(주기형) → 터렛(조준형).
5. **상태머신 함정군** → 튀는가시 · 낙하함정 · 압사기.
6. **점프대 · 위장발판** (독립적, 아무 때나).
