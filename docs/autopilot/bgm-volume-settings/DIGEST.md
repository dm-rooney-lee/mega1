### #1. 설정 패널 클릭 판정 — 코드 리뷰와 실제 실행이 갈렸던 지점
- **위치**: `src/scenes/SettingsScene.ts:73` (panel), `:145` (track)
- **컨텍스트**: 설정 화면의 슬라이더 패널을 클릭했을 때 "패널 안이면 안 닫히고, 바깥이면 닫힌다"가 제대로 동작하는지 검증하는 지점.
- **분기점**: 코드 리뷰(xhigh)가 Phaser 공식 소스 문서(Shape.setSize()는 이미 만들어진 클릭 판정 영역을 갱신하지 않는다는 문구)를 근거로 "패널 클릭 판정이 1x1로 고정돼 있어 거의 모든 클릭이 창을 닫아버린다"는 심각한 결함 2건을 보고했다. 그런데 실제로 브라우저를 띄워 패널 중심에서 150px 떨어진 지점을 클릭해보니(그리고 클릭 판정 영역의 실제 크기를 직접 읽어보니) 정상적으로 크기가 맞고 닫히지 않았다.
- **내 결정**: 고치지 않음 — 실제 실행 결과를 따름.
- **근거**: Phaser 공식 문서의 일반 설명과, 이 저장소에 실제로 설치된 Phaser 버전(4.2.1)의 실제 동작이 다르다는 것을 직접 확인했다(이유는 특정하지 못함 — Phaser 4의 특정 버전에서 문서가 아직 못 따라간 개선일 가능성).
- 👉 **혹시 나중에 설정 화면에서 "클릭해도 슬라이더가 안 움직인다"거나 "패널 안을 눌렀는데 창이 닫힌다"는 증상이 실제로 재현되면**: `src/scenes/SettingsScene.ts`의 `panel.setInteractive()`/`track.setInteractive()` 호출을 `layout()` 이후로 옮기거나, 명시적으로 `setInteractive(new Phaser.Geom.Rectangle(...))`로 크기를 매번 다시 지정하도록 고친다. 하니스 후보: 이번 검증 방식(Phaser 문서만으로 판단하지 않고 실제 실행 결과로 재확인)을 `.claude/rules/`에 일반 규칙으로 남길 만하다.

### #2. 화면별 배경음악 볼륨 차이를 완전히 없앤 것 — 취향이 갈릴 수 있는 결정
- **위치**: `src/config.ts` `BGM_VOLUME`, 스펙 문서
- **컨텍스트**: 타이틀·죽음·승리 화면의 배경음악이 이제 게임 플레이 중과 똑같은 크기(0.2)로 통일됨. 이전에는 이 화면들이 0.5로 더 크게 나왔다.
- **분기점**: 코드 리뷰(xhigh)가 "화면 전환할 때 음악이 더 이상 커지지 않는다"를 회귀(퇴보)로 지적했다. 하지만 이건 리뷰가 이번 작업의 배경(대화 맥락)을 모른 채 diff만 본 결과다 — 이번 세션 초반에 사용자가 이 통일을 정확히 이 방향으로 직접 선택했다(다른 대안: 화면별 차이는 유지하고 조절 기능만 추가하는 것도 있었음).
- **내 결정**: 그대로 둠 — 사용자의 명시적 선택.
- **근거**: 첫 번째 질문에서 "요청대로 전부 게임플레이 수준(0.2)로 통일 + 조절 기능 추가"를 사용자가 직접 골랐다.
- 👉 **막상 플레이해보니 타이틀/죽음/승리 화면 음악이 너무 조용하게 느껴지면**: `BGM_VOLUME`(현재 0.2) 값 하나만 올리면 4개 화면 전부에 반영된다(화면별로 다시 나눌 필요 없음).

### #3. 배경음악/효과음을 독립 슬라이더로 만든 것 — 의도된 트레이드오프
- **위치**: `src/scenes/SettingsScene.ts`, `src/settings.ts`
- **컨텍스트**: 배경음악과 효과음을 각각 따로 조절할 수 있다. 사용자가 효과음만 크게 낮추면 배경음악이 효과음보다 커지는 상황이 이론상 가능하다(원래 이 게임은 "배경음악 < 효과음"이 되도록 튠돼 있음).
- **분기점**: 코드 리뷰가 이 역전 가능성을 결함으로 지적했다. 하지만 이건 "각각 따로 조절" 방식을 선택할 때 이미 카드에 담아 사용자에게 고지했던 트레이드오프였다(대안: 전역 볼륨 하나만 두면 이 문제가 없었음).
- **내 결정**: 그대로 둠 — 사용자가 그 트레이드오프를 알고 "각각 따로"를 선택했다.
- **근거**: 세 번째 질문("조절 단위") 카드에 정확히 이 상황을 명시하고 사용자가 선택함.
- 👉 이게 실제로 불편하다고 느껴지면: 효과음이 배경음악보다 항상 커지도록 강제하는 로직을 추가할 수 있지만, 이는 사용자가 원하는 대로 조절하지 못하게 막는 것이므로 별도 요청 필요.

## ✅ 자신 있게 한 결정 (간략 리스트)
- [Task1] `settings.ts`에 localStorage 접근 실패/손상 시 기본값 폴백 + 인메모리 캐시 — 저장 실패해도 이번 세션 값 유지
- [Task2] `playBgm(scene, volume)` → `playBgm(scene)`로 단순화, 화면별 볼륨 상수 제거 — 통일이 유일한 이유
- [Task2] 효과음 볼륨을 0(완전 무음)으로 낮추면 Web Audio가 RangeError를 던지는 걸 발견해 수정 — 실사용에서 반드시 겪을 경로
- [Task3] `scene.launch()` 대신 `scene.run()` 사용 — Phaser가 이 정확한 모달 시나리오를 위해 문서화한 API
- [Task3] 톱니바퀴 아이콘을 유니코드 이모지가 아니라 기존 해저드 아이콘과 같은 방식(BootScene 절차적 드로잉)으로 그림 — 픽셀아트 일관성
- [Task3] 딤 배경을 인터랙티브로 만들지 않고 `currentlyOver.length === 0`로 "바깥 클릭" 판정 — 슬라이더 클릭과의 순서 모호성 회피
- [Task4] 톱니바퀴 클릭 시 `event.stopPropagation()` — 클릭 한 번이 설정도 열고 게임도 시작시키는 이중 발동 방지(3개 화면에서 실측 확인)
- [Task3 리뷰] 톱니바퀴 텍스처가 24x24 캔버스를 1px 벗어나 대칭이 깨졌던 것을 28x28로 수정, 슬라이더 손잡이/테두리가 화면 크기에 따라 같이 커지지 않던 것 수정
- [Task4 리뷰] 타이틀·죽음·승리 화면의 톱니바퀴가 `cameraZoom()` 배율 없이 배치되어 화면 크기에 따라 작아지고 구석에 붙어 있던 것을 수정 — 동시에 3개 화면에 중복돼 있던 톱니바퀴 생성 코드를 `screen.ts`의 `addSettingsGear()` 하나로 통합
- [사용자 리포트] 플레이 화면에서 "STAGE 1/10"과 톱니바퀴가 겹쳐 보인다는 리포트 → 같은 줄에 나란히 배치로 수정
- [재검토] 그 수정에서 중심 기준(origin) 좌표를 안 고려해 간격이 의도한 10px 대신 24px로 벌어졌던 것, 방패 아이콘 줄과 정렬이 깨지며 위쪽 여백이 6px로 줄었던 것 — 둘 다 재검토에서 잡혀 수정
- [재검토] settings.ts의 인메모리 캐시가 "한 번 읽고 계속 재사용"이라 다른 탭(또는 이전 성공 저장)의 값을 새 조절이 덮어쓸 수 있던 것 — "매번 새로 읽고, 저장 실패한 필드만 덮어쓰기"로 재설계
- [재검토] 효과음 볼륨 0 방지 로직이 두 곳에 중복되고 주석이 부정확했던 것 → 한 곳(`effectiveSfxVolume()`)으로 통합
- [재검토] 설정 슬라이더 드래그 중 손잡이 크기/테두리를 매 프레임 다시 계산하던 낭비 제거
