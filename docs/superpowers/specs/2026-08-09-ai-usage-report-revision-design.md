# AI 활용 보고서 재구성 설계

작성일: 2026-08-09

## 1. 개요 (무엇을 / 왜)

`docs/report/ai-usage-report.md`는 이미 한 차례 작성됐다(커밋 이력·설계 문서를 근거로 6개 섹션 구성). 그런데 다음 세 가지가 실제 요구와 맞지 않았다:

1. **어투와 시점**: 반말·3인칭 서술("~했다", "AI가 이렇게 활용되었다")로 되어 있어, 당사자가 직접 쓴 업무 보고서가 아니라 제3자가 관찰한 리포트처럼 읽힌다.
2. **구성 기준**: 지금 구성(개요/도구/프롬프트 작성 방식/활용 사례/정량 지표/배운 점)은 "AI를 어떻게 조사했는가"를 기준으로 짜여 있다. 실제로 AI를 쓴 활동은 개발·배경음악·디자인 세 영역으로 뚜렷이 나뉘는데, 지금 구성에는 이 구분이 드러나지 않는다.
3. **빠진 활동**: 배경음악은 Gemini의 음악 생성 기능으로, 화면 그림과 캐릭터·세계관 디자인은 Gemini의 이미지 생성 기능으로 초안을 만든 뒤 Claude Code로 다듬었다. 이 두 활동은 git 커밋만으로는 보이지 않는 작업(Gemini 쪽 산출물은 이 저장소 바깥에서 만들어짐)이라 기존 보고서에 전혀 반영되지 않았다.

이번 설계는 기존 보고서를 유지·재구성해 이 세 가지를 반영한다. 새로 조사하는 내용은 없다 — 지금 대화에서 이미 확인한 사실(아래 "근거 자료"의 커밋 해시·문서 경로)만 옮겨 쓴다.

## 2. 최종 설계

### 2.1 어투·시점 전환

- 반말(`~했다`) → 존댓말(`~했습니다`)
- 3인칭 관찰형(`AI가 ~하게 활용되었다`, `이 프로젝트는 ~했다`) → 1인칭 당사자형(`저는 ~했습니다`, `~를 만들 때는 ~했습니다`)
- 이 전환은 기존 문서 전체(6개 섹션)에 동일하게 적용한다.

### 2.2 섹션 구성 (확정)

기존 6개 섹션을 다음 구조로 재편한다.

```
1. 개요           (유지 + 핵심 숫자 2~3개를 문단 안에 녹여 넣음)
2. 사용한 AI 도구  (유지 + Gemini 추가)
3. 개발            (기존 "프롬프트 작성 방식" + "실제 활용 사례" 내용을 재구성)
4. 배경음악        (신규)
5. 디자인          (신규)
6. 배운 점 및 향후 계획 (유지, 위 섹션들을 다시 설명하지 않고 참조)
```

기존의 "정량적 지표" 섹션(커밋 수 표, 커밋 유형별 분류 표)은 **별도 섹션으로 두지 않는다.** 통계 자체가 AI 활용의 증거이긴 하지만, 유형별 분류표(feat/docs/fix...)는 AI 활용과 직접 관련 없는 일반적인 개발 통계이고, 서술형 보고서 중간에 표 두 개가 끼어들면 새로 지향하는 "당사자 서술" 톤과 맞지 않는다는 판단에 따라 뺀다. 대신 아래 2.3의 핵심 숫자만 개요 문단에 자연스럽게 포함시킨다.

### 2.3 섹션별 내용 (확정)

**1. 개요**

기존 문단 유지 + 아래 숫자 중 2~3개를 문장 안에 녹인다: 총 커밋 128건, 이 중 본인 커밋 116건의 67.2%에 AI가 공동작업자로 기록됨, 실제 작업일 7일. 표는 만들지 않고 문장으로만 쓴다.

**2. 사용한 AI 도구**

- 기존 Claude Code 설명 유지(존댓말·1인칭 전환)
- **Gemini**를 추가: 배경음악 생성과 이미지(그림) 생성 두 기능을 썼다고 명시. 두 도구를 어떤 작업에 썼는지는 3~5장에서 각각 설명하므로 여기서는 간단히 소개만 한다.

**3. 개발**

기존 "프롬프트 작성 방식"(3장)과 "실제 활용 사례"(4장)의 내용을 다음 흐름으로 재구성한다 — 새 사실 추가 없이 기존에 확인한 내용을 재배치:

- 반복 설명 대신 규칙 파일(`CLAUDE.md`)에 쌓아온 방식 (기존 3.1 내용)
- **CLAUDE.md를 처음 도입한 순간**: 2026-07-31, 커밋 `6eb57ba`("docs(rules,skills): add platformer development guidelines"), 설계 문서 `docs/superpowers/specs/2026-07-31-claude-context-management-design.md`. 이 문서가 CLAUDE.md·`.claude/rules`·Skill·git 훅의 역할을 처음 정의했다는 점을 새로 반영(이 설계 문서 자체는 기존 보고서 작성 시점에 조사했지만 본문에는 반영되지 않았던 자료다).
- (기존 정량 지표 섹션의 참고 문구를 여기로 옮김) **AI를 공동작업자로 표기하는 것과 CLAUDE.md를 도입한 것은 서로 다른 시점의 사건**이라는 구분은 삭제하지 않고 이 문단 안에 유지한다: 공동저자 표기 자체는 2026-07-24부터, CLAUDE.md 도입은 2026-07-31부터.
- 설계 → 계획 → 구현 → 검토의 반복 사이클 (기존 3.2, 스테이지 9-10 예시 + 다이어그램 유지)
- **개발 중 AI가 기대와 다르게 동작한 부분을 CLAUDE.md·rules에 반영해온 것**: 레티나 좌표 버그(`hazard-must-threaten.md`) 사례를 여기서 설명 — 볼륨 사례는 배경음악 섹션으로 옮긴다(4장 참고, 여기서는 중복 설명하지 않음)
- 반복 작업 표준화(`add-hazard-type` Skill), 다각도 교차 검토(스테이지 9-10, 결함 11건) — 기존 4장 (b)(c)(d) 내용 유지
- 이번 보고서 작성 요청 자체를 예시로 든 부분(기존 3.3)은 유지

**4. 배경음악** (신규)

- Gemini의 음악 생성 기능으로 배경음악을 만들었다는 사실을 먼저 서술
- 이 파일을 게임에 실제로 들여온 과정을 커밋으로 근거 제시: `e263e64`("feat(audio): add persistent looping background music", `public/audio/bgm.mp3` 추가) → 이후 씬이 바뀌어도 끊기지 않게 만든 작업(`cccef13` playBgm/stopBgm 분리, `ef5d54c` 화면별 재생 범위 지정)
- **볼륨 관례 미확인 사례를 여기로 이동**: "플레이 중 배경음악을 없애자"를 끝까지 구현했다가 되돌린 사건(`e84d101`), 실제 원인(볼륨 설정), 이후 `game-feel.md` 규칙화 — 기존 보고서의 3.1과 6장에 있던 내용을 여기로 모아 재서술(중복 제거)
- SFX(효과음)는 Web Audio로 즉석 합성한 것이라 Gemini와 무관하다는 점을 짧게 구분해서 언급(`docs/superpowers/specs/2026-08-06-sfx-synthesis-design.md` 근거) — 배경음악과 효과음의 출처가 다르다는 걸 명확히 하기 위함

**5. 디자인** (신규)

- Gemini의 이미지 생성 기능으로 두 종류의 초안을 만들었다는 사실을 먼저 서술: ① 타이틀·사망·클리어 화면 목업, ② 고퍼 캐릭터와 초원/숲/굴 세계관 배경
- Claude Code로 다듬은 과정을 설계 문서 근거로 구체적으로 서술:
  - 화면 목업(`docs/superpowers/specs/2026-08-08-title-death-win-screen-art-design.md`): 초안(시안 PNG)에 아이패드 화면틀, "final score: 9999", "SWIPE" 안내 같은 목업 특유의 요소가 섞여 있었는데, 이를 자동 벡터 변환하지 않고 실제 게임 화면 비율에 맞게 사각형·삼각형을 다시 나열해 그렸고, 이 게임에 없는 요소(점수판, 기기 테두리, 스와이프 조작)는 빼고 반영했다는 점을 서술
  - 세계관 에셋(`docs/superpowers/specs/2026-08-05-gopher-nature-assets-design.md`): 브레인스토밍 세션에서 여러 초안을 직접 비교해 스타일을 확정한 뒤, 기존 렌더링 방식(`fillRect` 조합)에 맞춰 픽셀 격자 스타일로 다시 그렸다는 점을 서술
- 두 사례 모두 "Gemini 초안 → 실제 게임 제약(비율·렌더링 방식·불필요 요소 제거)에 맞게 Claude가 다시 그림"이라는 같은 패턴이라는 점을 마지막에 한 문장으로 짚는다

**6. 배운 점 및 향후 계획**

- 기존 내용 유지, 다만 볼륨 사례가 이제 4장(배경음악)에서 설명되므로 "주의가 필요했던 것" 문단에서는 재설명 없이 "앞서 배경음악에서 설명한 사례처럼"로 참조만 한다.
- "향후 계획" 문단은 기존 그대로 유지(개발 규칙 관련 계획이라 개발/배경음악/디자인 구분과 무관하게 유효함).

## 4. 검토하지 않기로 한 것

- **"retrospective(demiurge)"라는 이름은 쓰지 않는다.** 저장소에 `demiurge`라는 이름이 붙은 것은 `docs/demiurge/rl-verify/` 디렉터리(설계 문서 사실 검증 기록) 하나뿐이라, 사용자가 말한 "AI가 의도와 다르게 동작하는 부분을 확인하고 CLAUDE.md·rules에 반영한 것"과는 다른 활동이다. 이 개념은 도구 이름 없이 "개발" 섹션 안에서 서술로만 반영한다.
- **정량적 지표를 별도 섹션·표로 두지 않는다.** 위 2.2에서 결정한 대로 핵심 숫자만 개요 문단에 녹인다. 유형별 분류표는 완전히 삭제한다.
- **Gemini 산출물 자체(실제 이미지 파일, 프롬프트)는 이 저장소에 없으므로 인용하지 않는다.** Claude Code가 다듬은 결과물(SVG, BootScene 그리기 코드)과 그 과정만 근거로 서술한다.

## 5. 완료 조건

- `docs/report/ai-usage-report.md`가 위 2.2의 6개 섹션 구조로 재작성되어 있다.
- 문서 전체가 존댓말·1인칭으로 되어 있고, 반말이나 3인칭 관찰형 문장이 남아있지 않다.
- "정량적 지표" 섹션(표 포함)이 삭제되어 있고, 핵심 숫자 2~3개는 개요 문단에 문장으로 남아있다.
- 배경음악·디자인 섹션에 Gemini 관련 서술이 있고, 각각 위 "근거 자료"의 커밋/문서가 인용되어 있다.
- 볼륨 사례가 배경음악 섹션에서만 상세히 설명되고, 배운 점 섹션에서는 중복 설명 없이 참조만 한다.
- 기존 보고서에 이미 있던 사실 검증 결과(예: AI 공동저자 67.2%, in-context-learning 관련 두 사건 구분)는 새 구조로 옮기는 과정에서 훼손되지 않는다.
