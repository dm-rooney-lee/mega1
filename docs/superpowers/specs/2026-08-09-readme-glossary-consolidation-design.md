# README·game-guide.md·glossary.md 경계 재정리 설계

## 배경

저장소에 게임 소개/설명 목적의 문서가 여러 개 생기면서 경계가 모호해졌다.

- `README.md` — 원래 저장소 설치·개발 문서인데, 최상단에 플레이 방법 한 줄도 이미 섞여 있었다.
- `docs/report/game-guide.md` — 플레이어를 위해 만든 문서(게임 개요/플레이 방법/실행 방법)지만, 만들고 보니 README와 대상 독자가 실질적으로 같다(둘 다 "이 저장소를 처음 열어본 사람").
- `docs/glossary.md` — 목적이 다르다. 개발자와 AI가 대화할 때 "차저", "감지 돌진적" 같은 한글 이름만으로 어떤 파일을 가리키는지 즉시 찾기 위한 이름↔코드 매핑 문서다(사용자 확인).

실제로 세 문서를 열어 대조한 결과 스테이지 이름·테마 표가 `game-guide.md`와 `glossary.md`에 거의 그대로 중복되어 있었고, `README.md`의 "수동 플레이테스트" 체크리스트에도 몹 이름이 또 나열되어 있었다. `glossary.md` 서두 문장은 `docs/CONTENT_REQUIREMENTS.md`를 유효한 참고 문서로 인용하고 있었지만, 실제로 열어보면 레벨이 1개뿐이던 초기 시점 내용이라 지금 코드와 맞지 않는다(별도 문제이므로 이번 정리에서는 그 인용만 없애고 파일 자체는 손대지 않는다).

이 설계는 "게임 개요·플레이 방법을 어디서 설명할지"와 "몹/기믹이 어떻게 동작하는지를 어디서 설명할지"의 출처를 각각 하나로 정하고, 나머지는 그곳을 링크하도록 재정리한다.

## 최종 역할 분담

| 문서 | 역할 | 대상 |
|---|---|---|
| `README.md` | 저장소의 단일 진입점 — 게임 개요, 플레이 방법(조작·승패·해저드 카테고리 요약), 설치·개발 실행, 빌드·배포 실행, 테스트 | 이 저장소를 처음 열어본 사람 전체(플레이어 + 개발자) |
| `docs/glossary.md` | 몹/기믹/스테이지의 한글 이름 ↔ 코드 식별자 매핑, 그리고 각 몹/기믹이 정확히 어떻게 동작하는지의 유일한 출처 | 코드를 고치거나 AI와 코드에 대해 대화하는 사람 |
| `docs/report/game-guide.md` | 삭제 | — |

`docs/CONTENT_REQUIREMENTS.md`(레벨 1개 시점의 낡은 명세)와 `docs/report/ai-usage-report.md`(무관한 문서)는 이번 정리 범위 밖이며 손대지 않는다.

## README.md 변경

### 구조

```
# 플랫포머 POC
(한 줄 소개만 유지 — 조작 힌트 문장, game-guide.md 링크 문장은 삭제)

## 게임 개요                    ← 신규
### 스테이지 구성 표

## 플레이 방법                  ← 신규
### 조작
### 목표와 승패
### 해저드 소개                 ← 카테고리 요약만, 개별 몹 상세는 glossary.md로 링크

## 사전 준비                    ← 기존, 변경 없음
## 게임 실행 (dev)              ← 기존, 변경 없음 (쿼리파라미터 설명 포함)
## 빌드된 파일로 실행하기        ← 신규
## 테스트                       ← 기존, "수동 플레이테스트" 체크리스트만 다듬음
```

### 신규 섹션 내용

"게임 개요", "플레이 방법 > 조작/목표와 승패", "빌드된 파일로 실행하기"는 `docs/report/game-guide.md`에 이미 작성되어 있고 코드 대조까지 마친 내용을 그대로 옮긴다(재작성하지 않음, 파일 경로 참조만 README 기준으로 바꿈 — 예: `../../README.md`처럼 상대경로였던 것을 제거).

"해저드 소개"만 아래처럼 축약한다 — 카테고리 이름과 카테고리 전체에 적용되는 공통 규칙 한 줄씩만 남기고, 개별 몹 5종의 항목별 설명(예: "감지 돌진적은 평소 느리게 왕복하다가...")은 삭제한다:

```markdown
### 해저드 소개

몹과 해저드가 16종 이상으로 많아 4개 카테고리로 나뉩니다. 각각의 정확한 동작은
[`docs/glossary.md`](docs/glossary.md)에 정리되어 있습니다.

- **밟아서 처치 가능한 몹** — 위에서 밟으면 처치, 옆/아래로 부딪히면 사망
- **발판·지형 기믹** — 밟고 지나가는 지형이지만 평범하지 않게 움직이거나 무너짐
- **고정 위험 요소** — 접촉하면 즉시 사망, 밟아서 처치할 수 없음
- **원거리 공격** — 발사체에 맞으면 사망(실드가 있으면 한 번 막아줌), 발사대 몸통을 어떻게 할 수 있는지는 종류마다 다름
```

### 기존 섹션 다듬기

"테스트 > 4. 수동 플레이테스트" 체크리스트 중 "스테이지 9·10의 신규 몹 4종" 항목은 몹 이름(망치 투척몹·공중 패트롤몹·감지 돌진적·수직 낙하몹)을 다시 나열하지 않고, "위 플레이 방법에 소개된 몹들이 정상 동작하는지"로 참조하도록 문구만 줄인다. 나머지 체크리스트 항목(이동/점프, 적 밟기, 죽음/승리 조건 등)은 그대로 둔다.

## docs/glossary.md 변경

### 서두 문장

현재:
> 이 문서는 게임 내 캐릭터·스테이지·몹·기믹의 한글 명칭과 실제 코드 식별자(클래스명·파일 경로)를 매핑합니다. 목적은 프롬프트나 대화에서 "차저", "감지 돌진적" 같은 이름만으로도 어떤 파일을 가리키는지 바로 찾을 수 있게 하는 것입니다. 몹·기믹의 동작 설명은 이미 [`docs/report/game-guide.md`](report/game-guide.md)와 [`docs/CONTENT_REQUIREMENTS.md`](CONTENT_REQUIREMENTS.md)에 정리되어 있으므로 여기서는 반복하지 않고, 그 문서들에 없는 코드 매핑만 채웁니다.

변경 후:
> 이 문서는 게임 내 캐릭터·스테이지·몹·기믹의 한글 명칭, 실제 코드 식별자(클래스명·파일 경로), 그리고 각 몹·기믹이 어떻게 동작하는지를 함께 정리합니다. 목적은 프롬프트나 대화에서 "차저", "감지 돌진적" 같은 이름만으로도 어떤 파일을 가리키고 어떻게 동작하는지 바로 찾을 수 있게 하는 것입니다. 게임을 처음 소개하는 내용(장르, 스테이지 구성, 조작법, 실행 방법)은 [`README.md`](../README.md)에 있으므로 여기서는 반복하지 않습니다.

(`docs/report/game-guide.md`·`docs/CONTENT_REQUIREMENTS.md` 인용 삭제, 목적 문장에 "동작 설명"을 포함하도록 수정 — 문서가 실제로 담을 내용과 자기소개가 어긋나지 않게 함.)

### 해저드 4개 카테고리 테이블에 "동작" 열 추가

기존 3열(한글 명칭 | 코드 식별자 | 파일) 표를 유지하면서 "동작" 열을 추가한다. 문장은 `docs/report/game-guide.md`에서 이미 코드 대조를 마친 설명을 표 셀에 맞게 간결한 구 단위로 옮긴다. 예:

```markdown
## 밟아서 처치 가능한 몹

| 한글 명칭 | 코드 식별자 | 파일 | 동작 |
|---|---|---|---|
| 기본 패트롤 적 | `Enemy` | `src/objects/Enemy.ts` | 정해진 구간을 왕복 |
| 망치 투척몹 | `HammerThrower` | `src/objects/HammerThrower.ts` | 걸어다니다 멈춰서 망치를 포물선으로 던짐(실드로 막을 수 없음) |
| 공중 패트롤몹 | `Flyer` | `src/objects/Flyer.ts` | 정해진 공중 경로를 왕복 |
| 감지 돌진적 | `Charger` | `src/objects/Charger.ts` | 평소 느리게 왕복, 근접 시 빠르게 돌진(돌진 중에도 처치 가능) |
| 수직 낙하몹 | `Dropper` | `src/objects/Dropper.ts` | 발판 위에서 대기, 아래로 지나가면 예고 후 낙하(실드로 막을 수 없음) |
```

같은 방식으로 "발판·지형 기믹", "고정 위험 요소", "원거리 공격" 표에도 "동작" 열을 추가한다(각 항목 문장은 삭제 대상인 `game-guide.md`의 해당 문장을 재사용).

### 스테이지 표

"테마" 열을 삭제하고 번호·배너 이름·레벨 파일만 남긴다(README의 "스테이지 구성" 표와 중복이므로). 표 위에 "테마 소개는 README.md 참고"를 한 줄 덧붙인다.

### 변경 없음

캐릭터, 기타 오브젝트, 배경 테마, 자연 리스킨 시각 별칭 표는 그대로 둔다.

## 파일 삭제

`docs/report/game-guide.md`를 삭제한다. `docs/report/ai-usage-report.md`는 무관하므로 유지한다.

## 완료 조건

- `docs/report/game-guide.md`가 삭제되어 있다.
- `README.md`에 "게임 개요"·"플레이 방법"·"빌드된 파일로 실행하기" 섹션이 있고, 최상단 소개 문단에는 조작 힌트·game-guide.md 링크 문장이 남아있지 않다.
- `docs/glossary.md`의 해저드 4개 카테고리 표 각각에 "동작" 열이 있고, 스테이지 표에는 "테마" 열이 없다.
- `docs/glossary.md` 서두 문장에 `docs/report/game-guide.md`·`docs/CONTENT_REQUIREMENTS.md` 참조가 남아있지 않다.
- 저장소 전체에서 `game-guide` 문자열을 검색했을 때 참조가 남아있지 않다(단, `docs/superpowers/plans/` 아래 과거 계획 문서는 기록이므로 그대로 둔다).
- `npm run build`, `npm test`가 통과한다(문서만 바뀌므로 회귀는 없어야 하지만 최종 확인).

## 하지 않는 것

- `docs/CONTENT_REQUIREMENTS.md`, `docs/PROJECT_ANALYSIS.md` 본문 정리 — 이번 범위 밖.
- `docs/report/ai-usage-report.md` — 무관.
- 코드(`src/`) 수정 — 이번 작업은 문서 재배치이며 코드는 건드리지 않는다.
