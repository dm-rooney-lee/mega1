# 배경음악 재생 범위 설계 — 게임 중에는 효과음만

작성일: 2026-08-08

> ⚠️ **이 문서의 1~12절은 첫 판이며, 일부는 더 이상 현재 동작이 아니다.** 플레이 중 완전 무음이 너무 허전하다는 판단에 따라 "음악을 끈다"를 "음악 볼륨을 낮춘다"로 바꿨다. **현재 동작은 13절**에 있고, 앞 절들은 그 결정에 이르기까지의 근거로 남겨둔다. 특히 2절의 전이표와 4절의 함수 목록은 13절이 대체한다.

## 1. 개요 (무엇을 / 왜)

지금은 배경음악이 한 번 켜지면 게임이 끝날 때까지 절대 꺼지지 않는다. 타이틀 화면에서 키를 누르는 순간 재생을 시작하고, 그 뒤로는 플레이 중이든 죽음 화면이든 승리 화면이든 계속 흐른다.

이번 작업은 배경음악을 **게임을 하지 않는 세 화면에서만** 나오게 바꾼다. 플레이 중에는 음악을 끄고 효과음만 남긴다. 장애물 소리·발사음·점프음이 음악에 묻히지 않게 하고, 플레이와 플레이 사이의 화면(타이틀·죽음·클리어)에 음악이 배치되어 리듬이 생긴다.

**게임 규칙·물리·난이도는 일절 변경하지 않는다. 효과음도 손대지 않는다.** 배경음악이 켜지고 꺼지는 시점만 바꾼다.

## 2. 확정된 동작

### 화면별 소리

| 화면 | 코드상 이름 | 지금 | 바꾼 뒤 |
|---|---|---|---|
| 타이틀 | `MenuScene` | 무음 (키를 누르는 순간 음악 시작) | 🎵 배경음악 |
| 플레이 | `GameScene` | 🎵 배경음악 + 효과음 | 효과음만 |
| 죽음 | `GameOverScene` | 🎵 (앞 화면에서 이어져 나올 뿐) | 🎵 배경음악 |
| 전체 클리어 | `WinScene` | 🎵 (앞 화면에서 이어져 나올 뿐) | 🎵 배경음악 |

### 곡

세 화면 모두 지금 있는 `public/audio/bgm.mp3` 한 곡을 그대로 쓴다. 새 음악 파일을 추가하지 않는다.

### 화면 이동별 음악 상태

```
        ┌──────────┐  키 입력   ┌──────────┐
   ────▶│  타이틀   │──────────▶│  플레이   │
        │   🎵     │           │  (효과음)  │
        └──────────┘           └──────────┘
             ▲                   │      │
       ESC   │            죽음   │      │  전체 클리어
             │                   ▼      ▼
        ┌────┴─────┐        ┌────────┐ ┌────────┐
        │          │◀───────│  죽음   │ │ 클리어  │
        └──────────┘  ESC   │   🎵   │ │  🎵    │
                            └────────┘ └────────┘
                                 │           │
                                 └─ 재시도 ──┴──▶ 플레이 (음악 정지)
```

| 이동 | 음악 |
|---|---|
| 실행 → 타이틀 | ▶ 재생 시작 *(브라우저가 허용할 때. 3절 참고)* |
| 타이틀 → 플레이 | ⏹ 정지 |
| 플레이 → 다음 스테이지 | ⏹ 정지 상태 유지 (끄기 요청이 아무 일도 하지 않음) |
| 플레이 → 죽음 | ▶ 재생 시작 |
| 플레이 → 전체 클리어 | ▶ 재생 시작 |
| 죽음 → 재시도 | ⏹ 정지 |
| 죽음 → 타이틀 (`ESC`) | 🎵 **끊김 없이 계속** |
| 클리어 → 다시하기 | ⏹ 정지 |
| 클리어 → 타이틀 (`ESC`) | 🎵 **끊김 없이 계속** |

마지막 두 줄이 이 설계에서 유일하게 자명하지 않은 동작이다. 죽음 화면과 타이틀 화면은 둘 다 음악이 필요한 구간이므로, 그 사이를 이동할 때 곡을 껐다 켜서 처음부터 다시 시작하는 대신 **이미 흐르는 곡을 그대로 둔다.** 4절의 "이미 재생 중이면 건드리지 않는다" 규칙이 이것을 만들어낸다.

## 3. 브라우저 자동재생 제약과 그 결과

브라우저는 사용자가 페이지를 한 번이라도 클릭하거나 키를 누르기 전에는 소리 재생을 차단한다. 광고 소음을 막기 위한 규칙이며 모든 웹사이트에 적용된다. 코드로 만들어낸 가짜 입력 이벤트로는 우회할 수 없다 — 브라우저가 이벤트마다 "진짜 사람에게서 온 것인가"를 표시해두고 그 표시가 있는 입력만 인정하기 때문이다.

지금 코드가 타이틀 화면이 뜨는 시점이 아니라 **키를 누르는 순간** 음악을 켜는 것도 이 때문으로 보인다. 그 지점이 브라우저가 소리를 허용하는 첫 순간이다.

그런데 이번 설계에서는 그 키 입력이 곧 플레이 시작이라, 음악이 켜지자마자 꺼진다.

```
[브라우저가 소리를 허용한 상태]
  타이틀 🎵 → 키 → 플레이 (효과음만)                      ← 의도대로 동작

[브라우저가 차단한 상태 = 탭을 새로 열고 첫 판]
  타이틀 (무음) → 키 → 음악이 켜지는 동시에 플레이 진입 → 정지   ← 사실상 안 들림
  이후 죽음 🎵 → ESC → 타이틀 🎵 → 플레이                  ← 정상 동작
```

**이 상태를 그대로 수용한다.** 탭을 새로 열고 시작하는 첫 판에서만 타이틀이 조용하고, 그 뒤로는 정상이다. 첫 입력 뒤에도 타이틀에 잠시 머물게 하거나 입력을 두 번 받는 방법으로 해결할 수 있지만, 두 방법 다 매 판 시작에 지연이나 추가 입력을 강요해서 값을 못 한다.

한편 브라우저가 알아서 허용해주는 경로도 있다. 크롬은 사용자가 그 사이트에서 소리 있는 미디어를 자주 재생했다고 판단하면 입력 없이도 자동재생을 허용하고, 사용자가 주소창에서 직접 소리를 허용해둘 수도 있다. **그래서 타이틀 화면에서는 조건 없이 재생을 요청한다.** 허용되는 사용자는 아무 입력 없이도 처음부터 음악을 듣고, 차단되면 조용히 무시될 뿐 오류가 나지 않는다.

## 4. 구조

### 오디오 모듈이 제공할 두 개의 문 (`src/audio.ts`)

현재의 `startBgmOnce()`(한 번 켜면 절대 안 끄는 함수)를 두 개로 대체한다.

```ts
/** 이미 재생 중이면 건드리지 않고, 아니면 곡을 처음부터 재생한다. */
export function playBgm(scene: Phaser.Scene): void

/** 재생 중이면 멈춘다. 다음 재생은 곡 처음부터 시작된다. */
export function stopBgm(): void
```

`stopBgm()`이 화면을 인자로 받지 않는 이유는 음악 객체가 모듈 안에 보관되어 있고 어떤 화면에도 속하지 않기 때문이다(5절에서 확인).

`playBgm()`은 음악을 만들거나 재생하다 실패하면 콘솔에 경고만 남기고 넘어간다. 지금 `startBgmOnce()`가 하는 방식 그대로이며, 소리 문제가 게임 진행을 막지 않는다는 기존 원칙을 유지한다. `stopBgm()`은 아직 음악이 만들어지지 않았으면 아무 일도 하지 않는다.

### 호출 지점 네 곳

| 파일 | 위치 | 호출 |
|---|---|---|
| `src/scenes/MenuScene.ts` | 타이틀 글자를 만들기 직전 (아래 설명) | `playBgm(this)` |
| `src/scenes/GameScene.ts` | `create()` 시작부 | `stopBgm()` |
| `src/scenes/GameOverScene.ts` | `create()` 시작부 | `playBgm(this)` |
| `src/scenes/WinScene.ts` | `create()` 시작부 | `playBgm(this)` |

### 타이틀 화면에서의 정확한 위치

`MenuScene.create()`는 앞부분에서 개발용 주소 파라미터(`?stage=7`)를 확인하고, 유효하면 타이틀을 건너뛰고 곧장 플레이 화면으로 들어간다(현재 18~41행).

음악을 켜는 호출은 **이 확인이 끝난 뒤**, 타이틀 글자를 만들기 직전에 둔다(현재 43행 `centredTextScreen` 호출 자리). `create()` 맨 앞에 두면 타이틀을 건너뛰는 경로에서도 음악이 켜졌다가 플레이 화면 진입과 동시에 꺼져, 아래에서 지우기로 한 동작이 그대로 되살아난다.

### 함께 지우는 것

같은 개발용 분기 안에 음악을 켜는 줄이 있다(현재 36행). 어차피 곧장 플레이 화면으로 들어가 꺼지므로 삭제한다. 위 배치와 합쳐, 타이틀을 건너뛰는 경로에서는 음악이 **처음부터 켜지지 않는다.**

### 음악을 끌 때 소리를 서서히 줄이지 않는다

즉시 멈춘다. 음악이 꺼지는 순간은 화면이 통째로 바뀌는 순간과 같아서, 딱 끊기는 편이 오히려 "플레이 시작"이라는 전환 신호로 읽힌다.

부드럽게 줄이려면 볼륨을 시간에 걸쳐 낮추는 애니메이션이 필요한데, 이 애니메이션은 화면에 소속되어 있어서 **줄어드는 도중에 화면이 또 바뀌면 볼륨이 중간값에 멈춘 채 남는다.** 그러면 다음번 음악이 작게 나오는 버그가 되고, 막으려면 재생할 때마다 볼륨을 되돌리는 방어 코드가 또 붙는다. 실제로 플레이해보고 끊김이 거슬리면 그때 넣는다.

## 6. 검토했으나 채택하지 않은 선택지

| 선택지 | 기각 사유 |
|---|---|
| 오디오 모듈이 화면 전환을 감시하고 "어느 화면에서 음악이 나야 하는가" 표로 자동 판단 | 화면이 4개뿐이고 늘어날 계획도 없다. 자동화의 이점(호출 빠뜨림 방지)이 아직 값을 못 한다. 각 화면에 한 줄씩 두면 파일을 열었을 때 그 화면이 음악을 켜는지가 바로 보이고, 지금 타이틀 화면이 음악을 직접 켜는 기존 흐름과도 이어진다 |
| 죽음·클리어 화면에 다른 곡을 쓰기 (파일 추가 또는 코드 합성) | 음악 파일을 새로 준비하는 부담, 또는 순음 합성 멜로디의 품질 한계. 한 곡으로 시작해보고 어색하면 나중에 나눈다 |
| 타이틀에서 키를 누른 뒤 잠시 머물다 플레이 시작 | 타이틀을 거치는 모든 판에 지연이 생긴다. 연속으로 재도전할 때 답답하다 |
| 타이틀에서 입력을 두 번 받기 (첫 입력은 음악만, 두 번째에 시작) | 키를 눌렀는데 게임이 안 시작하는 것처럼 느껴져 혼란스럽다 |
| 음악을 멈추는 대신 일시정지해서 플레이 후 이어듣기 | 플레이가 몇 분씩 이어지면 연속감이 어차피 사라지고, 죽음 화면에서 곡의 애매한 중간부터 시작되어 잘린 느낌이 난다 |

## 7. 효과음과 겹치지 않는지 확인

죽음·클리어 순간에는 이미 효과음이 울리고 있어서, 그 위에 음악이 덮치면 지저분해진다. 기존 코드의 시간 간격을 확인한 결과 여유가 있어 손댈 곳이 없다.

```
[죽음]     죽음 효과음 400ms  ▓▓▓▓░░░░░░░░░░░░░░░░
           화면 전환                        ↑ 800ms 후
                                            └─▶ 🎵 음악 시작    ✅ 400ms 여유

[클리어]   승리 효과음 360ms  ▓▓▓▓▓▓▓░░░
           화면 전환                   ↑ 500ms 후
                                       └─▶ 🎵 음악 시작        ✅ 140ms 여유
```

- 죽음 효과음 400ms: `src/config.ts`의 `SFX.DEATH`. 화면 전환 800ms: `GameScene.handleDeath()`
- 승리 효과음 360ms: `SFX.WIN`의 3음 × 120ms. 화면 전환 500ms: `GameScene.handleWin()`

## 8. 완료조건

### 자동 검증

```bash
npm run build   # 타입 검사 + 빌드 통과
npm test        # 기존 123개 + 오디오 모듈 신규 테스트 통과
```

오디오 모듈의 두 함수는 가짜 화면 객체로 검증한다. 이 프로젝트가 이미 쓰는 방식으로, `src/objects/hitbox.test.ts`가 가짜 스프라이트 객체를 만들어 Phaser 물리 동작을 검증하는 것과 같다. 검증 대상은 다음 세 가지다.

- 정상 흐름 — 아무것도 재생 중이 아닐 때 음악을 만들어 재생한다
- 경계 — 이미 재생 중이면 다시 만들지도 재생하지도 않는다 / 멈췄다 다시 켜면 기존 음악을 재사용한다 / 음악을 만들기 전에 끄기를 불러도 아무 일이 없다
- 예외 — 음악을 만들거나 재생하다 실패하면 예외를 밖으로 내보내지 않고 경고만 남긴다

**"이미 재생 중이면 건드리지 않는다"가 자동 검증의 핵심 대상이다.** 2절의 죽음 → 타이틀 이동에서 곡이 끊기지 않게 만드는 규칙이자, 이 설계에서 유일하게 자명하지 않은 동작이기 때문이다.

### 직접 플레이해서 확인 (`npm run dev`)

1. 타이틀에서 음악이 나온다 — 같은 탭에서 한 판 플레이한 뒤 타이틀로 돌아와 확인 (탭을 새로 연 첫 판은 3절에서 설명한 대로 무음일 수 있음)
2. 플레이에 들어가면 음악이 멈추고, 점프·적 처치 효과음은 그대로 난다
3. 죽으면 죽음 화면에서 음악이 나온다
4. 죽음 화면에서 `ESC`로 타이틀에 갈 때 음악이 끊기지 않는다
5. 죽음 화면에서 재시도하면 음악이 다시 멈춘다
6. 스테이지 1에서 2로 넘어갈 때 음악이 켜지지 않는다
7. 8개 스테이지를 전부 깨면 클리어 화면에서 음악이 나온다
8. 클리어 화면에서 `ESC`로 타이틀에 갈 때 음악이 끊기지 않는다

### 네 화면의 호출 배치는 직접 플레이로만 검증한다

각 화면에 한 줄씩 넣는 호출은 자동화 대상이 아니다. 그 줄이 있는지 확인하는 테스트는 코드를 그대로 옮겨 적는 것에 불과해 아무것도 보장하지 못하고, 실제로 확인해야 할 것("플레이 중에 음악이 안 들리는가")은 화면 전환과 브라우저 오디오가 얽힌 결과라 위의 직접 플레이 목록으로만 확인된다.

> **초안 정정** — 이 설계의 처음 판에는 "이번 변경은 전부 부수효과라 자동 검증할 대상이 없다"고 적혀 있었으나 **사실이 아니었다.** 실제로 돌려본 결과 오디오 모듈은 가짜 화면 객체로 문제없이 검증되며(테스트 환경에서 모듈이 정상 로드되고, 테스트 사이에 음악 상태도 초기화된다), 위에 적은 정상·경계·예외 케이스가 모두 통과했다. 자동 검증이 불가능한 범위는 오디오 모듈이 아니라 화면 배치 부분뿐이다.

## 9. 금지사항

- **음악을 새로 만드는 대신** 이미 있는 `public/audio/bgm.mp3`를 그대로 쓴다. 음악 파일을 추가하지 않는다.
- **효과음을 건드리는 대신** 배경음악의 재생 시점만 바꾼다. `src/config.ts`의 `SFX` 값과 11개 효과음 함수는 그대로 둔다.
- **화면 전환을 감시하는 구조를 만드는 대신** 각 화면이 직접 켜고 끈다.
- **소리를 서서히 줄이는 대신** 즉시 멈춘다.
- **음악이 안 나올 때 예외를 던지는 대신** 콘솔 경고만 남기고 게임을 계속 진행시킨다.
- **`startBgmOnce()`를 남겨둔 채 새 함수를 추가하는 대신** 그 함수를 두 함수로 대체한다. 쓰이지 않는 함수를 남기지 않는다.

## 10. 고려사항

- **플레이 화면에서 음악을 끄는 호출은 다음 스테이지로 넘어갈 때도 매번 실행된다.** 이미 멈춘 상태라 아무 일도 일어나지 않아야 한다 — 멈춘 음악에 다시 멈추라고 해도 안전하다는 것은 5절에서 확인했다.
- **죽음 화면과 클리어 화면은 재시도·다시하기로 플레이 화면에 돌아갈 수 있다.** 그때 음악이 확실히 꺼지는지가 위 확인 목록 5번이다.
- **개발용 주소 파라미터로 타이틀을 건너뛰는 경로**(`?stage=7`)에서는 음악이 아예 켜지지 않는다. 4절의 호출 위치가 이것을 보장한다.
- **화면 종료 처리에서 카메라가 이미 사라져 있을 수 있다는 이 프로젝트의 알려진 함정**은 여기 해당하지 않는다. 음악은 화면이 아니라 게임 전체에 보관되고, 끄는 호출도 화면 시작부에서만 일어난다.

## 11. 제약사항

- 브라우저 자동재생 정책은 우회할 수 없다. 탭을 새로 연 첫 판의 타이틀 무음은 코드로 해결되지 않는다(3절).
- 세 화면이 같은 곡을 쓰므로 화면별 분위기 차이가 없다. 죽음 화면에서 밝은 곡이 흐르는 것이 어색하면 곡을 나누는 후속 작업이 필요하다.
- 음악은 게임 전체에 하나뿐인 사운드 매니저가 보관하므로, 여러 곡을 동시에 다루게 되면 이 설계의 "하나의 음악 객체" 전제를 다시 봐야 한다.

## 12. 범위 밖 (보고만 하고 손대지 않음)

음악 볼륨 `0.5`가 `src/audio.ts:13`에 직접 적혀 있다. 이 프로젝트는 튜닝 수치를 `src/config.ts`에 모으도록 하고 있어 엄밀히는 규칙에서 벗어나 있지만, 이번 작업과 무관하고 그 줄을 건드릴 필요도 없어 그대로 둔다.

## 13. 개정 — 플레이 중에는 끄지 않고 볼륨만 낮춘다 (현재 동작)

### 왜 바꿨나

첫 판대로 만들어 보니 **플레이 중 완전 무음이 허전했다.** 그리고 원래 문제를 다시 보니 원인이 다른 데 있었다.

```
바꾸기 전 볼륨
  배경음악  0.5   ← src/audio.ts 에 직접 적혀 있던 값
  효과음    0.4   ← src/config.ts 의 SFX.MASTER_VOLUME

음악이 효과음보다 컸다.
```

효과음은 대부분 100~200ms짜리 짧은 소리라 체감상 더 작게 들린다. 즉 "플레이 중에 효과음이 안 들린다"의 원인은 음악의 **존재**가 아니라 **균형**이었다. 대부분의 플랫포머(마리오, 소닉, 셀레스트 등)는 플레이 중에도 음악을 계속 틀고, 대신 음악을 효과음보다 낮게 깔아 효과음이 위로 튀어나오게 한다.

### 현재 동작

음악은 한 번 켜지면 **멈추지 않는다.** 화면이 바뀔 때 볼륨만 달라진다.

```
   음량
    ▲
0.5 │ ░░░░░░░           ░░░░░░░░░      ← 타이틀·죽음·클리어 (음악이 주인공)
    │ ░░░░░░░           ░░░░░░░░░
0.4 │ ─────────  ▓▓  ▓▓ ─────────      ← 효과음 (짧고 크게, 위로 튄다)
0.2 │           ░░░░░░░               ← 플레이 중 (배경으로 물러남)
    └──────────────────────────────▶
       타이틀    플레이     죽음
```

| 화면 이동 | 음악 |
|---|---|
| 실행 → 타이틀 | ▶ `BGM.SCREEN`으로 시작 *(브라우저가 허용할 때. 3절 참고)* |
| 타이틀 → 플레이 | 🔉 `BGM.GAMEPLAY`로 낮아짐 (끊기지 않음) |
| 플레이 → 다음 스테이지 | 그대로 `BGM.GAMEPLAY` |
| 플레이 → 죽음 | 🔊 `BGM.SCREEN`으로 올라감 |
| 플레이 → 전체 클리어 | 🔊 `BGM.SCREEN`으로 올라감 |
| 죽음 → 재시도 | 🔉 `BGM.GAMEPLAY`로 낮아짐 |
| 죽음 → 타이틀 (`ESC`) | 그대로 `BGM.SCREEN` |
| 클리어 → 다시하기 | 🔉 `BGM.GAMEPLAY`로 낮아짐 |
| 클리어 → 타이틀 (`ESC`) | 그대로 `BGM.SCREEN` |

**곡은 어느 경우에도 처음부터 다시 시작하지 않는다.** 이것이 4절의 "이미 재생 중이면 건드리지 않는다" 규칙을 대체한다.

### 구조 변경

`src/audio.ts`의 함수가 하나로 줄었다.

```ts
/** 음악이 volume으로 흐르게 만든다. 안 켜졌으면 켜고, 흐르고 있으면 볼륨만 바꾼다. */
export function playBgm(scene: Phaser.Scene, volume: number): void
```

`stopBgm()`은 삭제했다. 음악이 멈추는 경우가 없어져 아무도 부르지 않게 됐기 때문이다.

볼륨은 `src/config.ts`로 옮겼다 — 귀로 듣고 조정할 값이고, 이 프로젝트는 그런 값을 `config.ts`에 모은다. **12절이 "범위 밖"으로 미뤄뒀던 항목이 여기서 해소됐다.**

```ts
export const BGM = {
  SCREEN: 0.5,    // 타이틀·게임오버·승리
  GAMEPLAY: 0.2,  // 플레이 중
} as const;
```

`BGM.GAMEPLAY`가 `SFX.MASTER_VOLUME`(0.4)보다 확실히 낮아야 효과음이 들린다. 이 관계가 깨지면 원래 문제로 되돌아간다.

### 호출 지점

| 파일 | 호출 |
|---|---|
| `src/scenes/MenuScene.ts` | `playBgm(this, BGM.SCREEN)` |
| `src/scenes/GameScene.ts` | `playBgm(this, BGM.GAMEPLAY)` |
| `src/scenes/GameOverScene.ts` | `playBgm(this, BGM.SCREEN)` |
| `src/scenes/WinScene.ts` | `playBgm(this, BGM.SCREEN)` |

개발용 주소 파라미터(`?stage=N`)로 타이틀을 건너뛰면 플레이 화면이 `BGM.GAMEPLAY`로 음악을 시작한다. 4절에서 "음악이 아예 켜지지 않는다"고 한 부분이 이렇게 바뀐다.

### 검증한 Phaser 동작 (추측 아님)

| 확인한 것 | 결과 |
|---|---|
| 재생 중인 음악의 볼륨을 바꿀 수 있는가 | ✅ `setVolume(v)`가 게인 노드를 즉시 바꾼다 (`WebAudioSound.js:939-966`) |
| `Phaser.Sound.BaseSound` 타입에 `setVolume`이 있는가 | ❌ 없다. 타입 검사를 통과하려면 `sound.add()`가 실제로 돌려주는 타입을 써야 한다 |

두 번째 항목 때문에 `bgm` 변수의 타입을 `ReturnType<Phaser.Scene["sound"]["add"]>`로 바꿨다. 런타임에는 원래 있던 메서드인데 타입 정의에만 빠져 있다.

### 볼륨은 뚝 바뀐다 (페이드 없음)

화면이 통째로 바뀌는 순간과 같아서 자연스럽고, 4절이 페이드를 기각한 이유(볼륨이 중간값에 멈춘 채 남을 위험)가 그대로 적용된다. 들어보고 거슬리면 그때 다시 본다.

### 확인 방법

8절의 아홉 가지 확인은 그대로 쓰되, "음악이 멈춘다"를 **"음악이 작아진다"**로 읽는다. 2번은 "플레이 중에 음악이 작게 깔리고 점프·적 처치 효과음이 그 위로 뚜렷하게 들린다"가 된다.
