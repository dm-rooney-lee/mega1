# 배경음악 볼륨 통일 + 사용자 볼륨 조절 기능 설계

작성일: 2026-08-09

## 1. 개요 (무엇을 / 왜)

"게임 볼륨이 너무 크다"는 피드백이 반복되어 두 가지를 바꾼다.

1. **배경음악(BGM: Background Music, 배경에 흐르는 음악) 볼륨을 화면 전체에서 통일한다.** 지금은 타이틀·죽음·승리 화면(`BGM.SCREEN = 0.5`)이 게임 플레이 중(`BGM.GAMEPLAY = 0.2`)보다 크게 나온다. 이 차이를 없애고 모든 화면이 지금의 플레이 중 볼륨(0.2)으로 통일된다.
2. **사용자가 직접 배경음악·효과음(SFX: Sound Effects, 점프·충돌 등의 짧은 효과음) 볼륨을 낮출 수 있는 설정 기능을 추가한다.** 톱니바퀴 아이콘으로 열고, 슬라이더로 조절하고, 브라우저에 저장되어 다음에 다시 열어도 유지된다.

이 문서는 두 변경을 하나의 설계로 함께 다룬다 — 2번을 구현하려면 어차피 볼륨 계산 경로를 `config.ts`의 고정값에서 "고정값 × 사용자 설정값"으로 바꿔야 하고, 그 김에 1번(화면별 차이 제거)도 같은 경로에서 처리하는 것이 더 단순하기 때문이다.

**게임 규칙·물리·난이도는 변경하지 않는다.** 효과음의 소리 자체(주파수·길이 등)도 바꾸지 않는다 — 크기만 바뀐다.

### 이전 결정과의 관계

`docs/superpowers/specs/2026-08-08-bgm-scene-scoped-design.md`의 13절이 지금의 화면별 볼륨 차이(`BGM.SCREEN`/`BGM.GAMEPLAY`)를 만든 결정이다. 이번 설계는 그 차이를 없애는 것이므로, 구현 시 그 문서 13절 상단에 "이후 통일됐다"는 짧은 안내를 추가한다(그 문서 자체가 5절에서 "1~12절은 낡았고 13절이 현재"라고 표시하는 것과 같은 방식).

## 2. 확정된 동작

### 2.1 배경음악 볼륨 통일

| 화면 | 지금 | 바꾼 뒤 |
|---|---|---|
| 타이틀 (`MenuScene`) | 0.5 | 0.2 × 사용자 배경음악 배율 |
| 플레이 (`GameScene`) | 0.2 | 0.2 × 사용자 배경음악 배율 |
| 죽음 (`GameOverScene`) | 0.5 | 0.2 × 사용자 배경음악 배율 |
| 승리 (`WinScene`) | 0.5 | 0.2 × 사용자 배경음악 배율 |

효과음 기준값(`SFX.MASTER_VOLUME = 0.4`)은 그대로 둔다. 통일된 배경음악 값(0.2)이 여전히 그보다 낮으므로, `.claude/rules/game-feel.md`가 요구하는 "배경음악 < 효과음" 관계는 깨지지 않는다.

### 2.2 사용자 볼륨 조절

- 톱니바퀴(⚙) 아이콘을 **타이틀·플레이·죽음·승리 4개 화면 전부**에 둔다.
- 클릭/탭하면 지금 화면을 일시정지하고, 그 위에 **반투명 검정 오버레이 + 레트로 테두리 박스**를 띄운다(`SettingsScene`). 물리·타이머·애니메이션이 전부 멈춘 상태로 화면이 얼어붙는다.
- 박스 안에는 "배경음악"/"효과음" 두 줄, 각 줄에 **드래그로 움직이는 연속 슬라이더**가 있다. 손잡이는 사각형(픽셀 느낌), 값은 오른쪽에 퍼센트로 표시한다.
- 슬라이더는 **0%~100%**이고 **100%는 지금 튠된 기본값**(배경음악 0.2, 효과음 0.4)이다. 100%보다 키울 수는 없고, 낮추는 것만 가능하다.
- 배경음악 슬라이더를 움직이면 지금 흐르고 있는 곡의 크기가 **바로 그 자리에서** 바뀐다(끊기거나 다시 시작하지 않는다). 효과음 슬라이더는 지속되는 소리가 없어 조작 중 들리는 소리는 없고, 다음에 실제로 그 효과음이 날 때부터 새 크기로 들린다.
- 닫는 방법은 **`ESC` 키** 또는 **박스 바깥(딤 처리된 배경) 클릭/탭** 두 가지다. 닫으면 열었던 화면이 멈췄던 지점에서 정확히 이어진다 — 플레이 중이었다면 죽지도, 스테이지가 처음부터 다시 시작되지도 않는다.
- 조절한 값은 **브라우저에 저장**되어, 탭을 닫고 다시 열어도(새로고침 포함) 유지된다.

### 2.3 화면 전환 다이어그램

```
┌───────────┐  gear 클릭   ┌──────────────┐
│ MenuScene │ ───────────▶ │              │
├───────────┤              │              │  ESC 또는
│ GameScene │ ───────────▶ │ SettingsScene│  딤 배경 클릭
├───────────┤              │  (오버레이,   │ ─────┐
│GameOverSc.│ ───────────▶ │  일시정지 중) │       │
├───────────┤              │              │       │
│ WinScene  │ ───────────▶ │              │       │
└───────────┘              └──────────────┘       │
      ▲                                            │
      └── 멈췄던 지점에서 정확히 재개 ───────────────┘
```

## 3. 구조

### 3.1 `src/config.ts` — 볼륨 상수 단순화

```ts
/** 배경음악 볼륨(사용자 설정을 곱하기 전 기준값). 모든 화면이 이 값 하나를 쓴다. */
export const BGM_VOLUME = 0.2;
```

기존의 `export const BGM = { SCREEN: 0.5, GAMEPLAY: 0.2 }`를 대체한다. 값이 하나뿐이라 객체로 묶을 이유가 없어진다. `SFX.MASTER_VOLUME`은 손대지 않는다.

### 3.2 `src/settings.ts` (신설) — 사용자 볼륨 배율의 저장/조회

Phaser에 의존하지 않는 순수 모듈이다(`src/audio.ts`, `src/scenes/*`가 이 값을 읽고 쓴다).

```ts
/** 0~1. 저장된 값이 없거나 읽기에 실패하면 1(=100%, 원래 크기)로 취급한다. */
export function getBgmVolume(): number
export function getSfxVolume(): number

/** 0~1 범위로 잘라서(clamp) 저장한다. 저장에 실패해도 예외를 던지지 않는다. */
export function setBgmVolume(value: number): void
export function setSfxVolume(value: number): void
```

- 저장은 `localStorage`에 `{ bgm: number, sfx: number }` 형태의 JSON 하나로 한다.
- **프라이빗 브라우징 등으로 `localStorage` 접근 자체가 예외를 던지는 경우, 값이 깨져 있는 경우, 저장된 적이 없는 경우** 모두 기본값(1)으로 조용히 폴백한다 — `src/audio.ts`가 오디오 실패를 조용히 넘기는 것과 같은 원칙이다.
- 범위 밖 값(`-0.3`, `1.7` 등)이 저장을 요청받으면 0~1로 잘라서 저장한다.

### 3.3 `src/audio.ts` — 볼륨 계산 경로 변경

- `playBgm(scene: Phaser.Scene): void`로 시그니처를 바꾼다(볼륨 인자 제거). 내부적으로 `BGM_VOLUME * getBgmVolume()`을 재생 볼륨으로 쓴다.
- 설정 화면에서 배경음악 슬라이더를 드래그하는 동안 지금 흐르는 곡에 실시간으로 반영해야 하므로, `setVolume`을 다시 호출해 반영하는 함수를 하나 더 내보낸다(예: `refreshBgmVolume(): void` — 이미 만들어진 음악 객체가 있으면 `BGM_VOLUME * getBgmVolume()`로 볼륨을 다시 맞춘다. 없으면 아무 일도 하지 않는다).
- `playJump`/`playEnemyKill`/`playFire`/`playCannonFire`/`playShieldBlock`/`playRockDrop`/`playDeath`/`playPendulumSwing`/`playWin`/`playShieldPickup`/`playSpringBounce` — 지금 전부 `SFX.MASTER_VOLUME`을 그대로 넘기는 자리를, `SFX.MASTER_VOLUME * getSfxVolume()`을 계산하는 작은 헬퍼로 바꾼다.

### 3.4 `src/scenes/SettingsScene.ts` (신설)

- `init(data: { returnKey: string })`로 어느 화면 위에 열렸는지 받는다.
- `create()`: 화면 전체를 반투명 검정 사각형으로 덮고, 중앙에 레트로 테두리 박스를 그린다. 박스 안에 제목("SETTINGS")과 배경음악·효과음 슬라이더 2줄.
- **새 색상을 만들지 않는다.** 글꼴은 `screen.ts`가 쓰는 `SCREEN_FONT`("Press Start 2P")를 그대로 쓰고, 박스 배경·글자색은 `SCREEN_COLORS`(예: `TITLE_SKY`, `PROMPT`, `MUTED`)에서 고르고, 슬라이더 채움색은 `COLORS`에 이미 있는 값(예: `PLAYER`의 `0x29adff`, `GOAL`의 `0x00e436`)에서 고른다. 이 화면만을 위한 새 팔레트를 추가하면 다른 3개 화면과 색이 어긋난다.
- 슬라이더는 Phaser의 포인터 드래그 이벤트로 손잡이를 움직이고, 값이 바뀔 때마다 `setBgmVolume`/`setSfxVolume`을 호출해 저장하고, 배경음악 슬라이더는 추가로 `refreshBgmVolume()`을 호출해 즉시 반영한다.
- `ESC` 키다운 또는 딤 배경 클릭 시: `this.scene.resume(returnKey)` 후 자기 자신을 정지(`this.scene.stop()`).

### 3.5 4개 화면에 톱니바퀴 아이콘 추가

`MenuScene`/`GameScene`/`GameOverScene`/`WinScene`의 `create()`에 클릭/탭 가능한 아이콘을 하나씩 그리고, 누르면 `this.scene.pause()` 후 `this.scene.launch("SettingsScene", { returnKey: this.scene.key })`를 부른다.

- `GameScene`에서는 기존 HUD(우측 상단 `STAGE N/10`)와 겹치지 않는 위치에 둔다. `GameScene.layoutHud()`가 이미 `cameras.main.worldView` 기준으로 HUD를 재배치하는 로직을 갖고 있으므로, 톱니바퀴도 그 로직 안에서 같은 방식으로 배치한다(이 프로젝트가 `.claude/rules`에서 강조하는, 화면 크기에 따라 위치가 계산돼야 하는 요소이기 때문).
- 나머지 3개 화면은 `centredScreen`이 만드는 고정 배치 화면이라, 톱니바퀴는 그 레이아웃 시스템 바깥에 화면 모서리 절대 위치로 둔다.

**아이콘은 유니코드 글자(⚙)나 시스템 폰트가 아니라, 이 게임의 다른 UI 그림(`TEX.UI_TITLE`, `TEX.UI_DEATH`, `TEX.UI_WIN`)과 같은 방식으로 그린다.** 이 프로젝트는 모든 그림을 `BootScene`에서 `beginTexture()`/`endTexture()`로 직접 픽셀을 찍어 만든다(`CLAUDE.md`의 "알려진 함정" 절) — 유니코드 이모지는 이 파이프라인을 벗어나 시스템 폰트로 렌더링되므로 나머지 픽셀아트와 이질감이 난다. 톱니바퀴도 새 텍스처(`TEX.UI_GEAR`류)로 `BootScene`에 추가하고, 스프라이트로 쓸 때는 `setDisplaySize()`로 논리 크기로 되돌린다(같은 절이 경고하는 "텍스처가 `TEXTURE_SCALE`배로 커진 채 남는" 실수를 피한다).

## 4. 확인이 필요한 기술적 위험 (구현 중 검증, 추측 금지)

- **`scene.pause()`가 그 씬의 입력 리스너까지 멈추는지 실제로 확인한다.** `MenuScene`은 `this.input.keyboard!.once("keydown", start)`와 `this.input.once("pointerdown", start)`로 "아무 키/클릭 → 게임 시작"을 걸어 둔다. `GameOverScene`/`WinScene`도 비슷하게 `.once()` 리스너가 있다. `SettingsScene`을 그 위에 얹었을 때 이 리스너들이 여전히 살아있으면, 설정 화면에서 슬라이더를 조작하려고 클릭한 것이 뒤에서 "재시도/시작"으로도 처리되는 버그가 생길 수 있다. Phaser 소스나 실제 동작으로 확인하고, 살아있다면 열 때 `scene.input.enabled = false`로 명시적으로 꺼야 한다.
- **`GameScene`의 물리 스텝이 씬 일시정지로 확실히 멈추는지 확인한다.** 이 프로젝트는 120Hz 고정 스텝 물리를 쓰고, `main.ts`의 fps 보정 로직과도 얽혀 있다 — `scene.pause()`가 그 시스템까지 멈추는지 실제로 재생해 확인한다(추측하지 않는다).

## 5. 완료조건

### 자동 검증

```bash
npm run build   # 타입 검사 + 빌드 통과
npm test        # 기존 테스트 + 아래 신규/수정 테스트 통과
```

- **`src/settings.ts` 신규 테스트** (Phaser에 의존하지 않는 순수 로직):
  - `[Happy]` `setBgmVolume(0.6)` 후 `getBgmVolume()`이 `0.6`을 반환한다.
  - `[Boundary]` 저장된 값이 없을 때 `getBgmVolume()`/`getSfxVolume()`이 기본값 `1`을 반환한다. `setBgmVolume(-0.3)`은 `0`으로, `setBgmVolume(1.7)`은 `1`로 잘려 저장된다. 경계값 `0`과 `1` 자체도 그대로 저장·조회된다.
  - `[Error]` `localStorage`에 깨진 JSON이 들어있을 때, 또는 `localStorage` 접근 자체가 예외를 던지는 환경에서 기본값(`1`)으로 폴백하고 예외를 밖으로 내보내지 않는다.
- **`src/audio.test.ts` 수정**: `playBgm(scene, volume)` 2개 인자 호출을 전제로 한 기존 테스트를 `playBgm(scene)` 1개 인자로 고치고, 재생된 볼륨이 `BGM_VOLUME * getBgmVolume()`(기본값일 때는 `0.2`)인지 검증하도록 바꾼다. `getBgmVolume()`을 모킹해 배율이 반영되는 경우도 추가한다.

### 수동 플레이테스트 (`npm run dev`)

1. 타이틀·플레이·죽음·승리 4개 화면 모두에서 배경음악 크기가 같게 들린다(전환할 때 갑자기 커지거나 작아지지 않는다).
2. 4개 화면 모두에서 톱니바퀴를 누르면 설정 화면이 뜬다.
3. 플레이 중 설정을 열면 캐릭터·적·발사체가 그 자리에서 완전히 멈춘다.
4. 배경음악 슬라이더를 드래그하면 지금 흐르는 음악 크기가 실시간으로 바뀐다.
5. 효과음 슬라이더를 낮춘 뒤 설정을 닫고 점프해보면 점프음이 작게 난다.
6. `ESC`와 딤 배경 클릭 둘 다로 설정 화면이 닫히고, 플레이 중이었다면 죽지 않고 그 지점에서 이어진다.
7. 설정 화면 위에서 아무 키를 누르거나 클릭해도 뒤의 타이틀/죽음/승리 화면이 몰래 다음 동작(시작/재시도)으로 넘어가지 않는다(4절의 위험 확인).
8. 값을 낮춘 뒤 브라우저를 새로고침해도 슬라이더 위치와 실제 소리 크기가 유지된다.

## 6. 금지사항

- **효과음의 소리 자체(주파수·길이 등)는 건드리지 않는다.** 크기(볼륨)만 바뀐다.
- **슬라이더로 기본값보다 크게 키우는 기능은 넣지 않는다.** 100%가 상한이다.
- **효과음 슬라이더에 미리듣기 소리를 재생하는 기능은 이번 범위에 넣지 않는다.** 요청받지 않은 기능이며, 필요성이 확인되면 후속 작업으로 검토한다.
- **씬 전환 감시용 전역 상태 관리자를 새로 만들지 않는다.** 각 화면이 직접 톱니바퀴를 그리고 직접 `SettingsScene`을 연다 — 지금 각 화면이 직접 `playBgm`을 부르는 것과 같은 결로 통일한다.
- **`localStorage` 접근 실패로 게임이 멈추거나 예외가 새어 나가게 하지 않는다.**

## 7. 고려사항

- **`GameOverScene`/`WinScene`은 재시도·다시하기로 `GameScene`으로 돌아갈 수 있다.** 설정 화면을 열었다가 닫는 경로가 이 재시도 흐름과 얽히지 않는지(예: 설정을 여러 번 열고 닫아도 씬이 중복으로 쌓이지 않는지) 확인한다.
- **개발용 주소 파라미터(`?stage=N`)로 타이틀을 건너뛰는 경로**에서도 톱니바퀴가 정상 동작해야 한다 — 이 경로는 `MenuScene.create()`를 거치지 않고 곧장 `GameScene`으로 들어가므로, 톱니바퀴는 `GameScene` 쪽에만 있으면 충분하다.
- **화면 크기(가로 854~1100 가변)에 따라 톱니바퀴와 설정 박스 위치가 깨지지 않는지** 창을 늘리고 줄여서 확인한다 — 이 프로젝트의 알려진 함정(카메라 배율, `worldView` 기준 배치)이 여기도 적용된다.

## 8. 제약사항

- 효과음은 매번 새로 합성되는 소리라(재생 중인 객체가 없음), 슬라이더를 움직이는 동안 실시간으로 들려줄 방법이 없다 — 2.2/6절에서 다룬 대로 이번 범위에서는 받아들인다.
- 배경음악 오디오 파일(`public/audio/bgm.mp3`)과 효과음 합성 로직 자체는 바꾸지 않는다.
