# 스테이지 9·10 + 신규 몹 4종 설계

## 배경

스테이지가 8개뿐이라 더 긴 도전이 필요하다는 요청으로 시작했다. 요구사항:

- 새 스테이지 2개(9, 10). 둘 다 길이가 스테이지1(2400px)의 3배 ≈ **7200px**.
- 신규 몹 4종(사용자 협의 중 "망치 투척몹 포함 3종"에서 "포함 3종 + 후보 3개 전부"로 확장 승인):
  1. **망치 투척몹** — 포물선으로 망치를 던짐 (최초 요청)
  2. **공중 패트롤몹**
  3. **감지 돌진적**
  4. **수직 낙하몹**
- 두 스테이지 모두 기존 8개 스테이지의 몹·기믹을 총동원하고, 신규 4종으로 난이도를 높인다.

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 스테이지 길이 | 9·10 모두 약 7200px |
| 배경 테마 | 기존 `underground` 재사용(신규 아트 없음) |
| 구현 경로 | 기존 `HazardDef` 확장(`add-hazard-type` 절차) — `enemies` 스키마는 새로 안 만듦 |
| 4종 몹의 스톰프 가능 여부 | 전부 가능 |
| 망치 투척몹의 이동 | 패트롤형(기존 `Enemy`처럼 왕복) |
| 망치 투척몹의 투척 | 고정 사거리/궤적(조준 안 함, `Cannon`과 동일 성격) |
| 감지 돌진적의 스톰프 | 돌진 중에도 항상 가능 |
| 수직 낙하몹의 배치 | 발판 위에 서서(Turret처럼) 밟으면 처치 가능 |

## 데이터 모델 (`src/levels/types.ts`의 `HazardDef` 유니온에 추가)

| kind | 이동 방식 | 위협 방식 | 필드 |
|---|---|---|---|
| `hammerThrower` | `Enemy`처럼 좌우 왕복 | 몸에 닿으면 즉사 + 주기적으로 포물선 망치 투척 | `x, y`(왕복 시작점, 서 있는 표면), `throwIntervalMs?` |
| `flyer` | `Gear`와 같은 축+거리 왕복(공중) | 몸에 닿으면 즉사 | `x, y, axis?, range?, speed?, phase?, waitMs?` |
| `charger` | `Enemy`처럼 왕복하다 플레이어 감지 시 돌진 | 몸에 닿으면 즉사(순찰·돌진 공통) | `x, y`, `detectRangeX?`, `chargeSpeed?` |
| `dropper` | 이동 없음, 발판 위 고정(`Turret`처럼) | 몸에 닿으면 즉사 + 감지 시 예고 후 수직 낙하 발사체 | `x, y`, `detectRangeX?`, `telegraphMs?` |

## 위협 판정(`threat.ts`) 방식 — 조사 후 단순화

처음엔 "망치의 포물선이 서 있는 몸통 높이를 지나는 x구간"을 새로 계산해야 한다고 가정했으나, 코드를 확인한 결과 더 단순한 길이 있다:

- 4종 몹 모두 **몸 자체가 닿으면 즉사**하는 근접 위협이다(기존 `Enemy`/`Turret`과 동일한 스톰프-아니면-즉사 규칙). 이 근접 위협만으로 `.claude/rules/hazard-must-threaten.md`의 "서 있는 주인공을 맞힐 수 있는가" 요건을 이미 충족한다.
- 따라서 `threat.ts` 등록은:
  - `hammerThrower`/`charger`: 이미 있는 `patrolBoundsFor()`(순수 함수, `src/levels/patrol.ts`)를 그대로 호출해 왕복 구간을 구하고, 그 구간 전체를 서 있는 몸통 높이 밴드로 등록한다. 던지는 망치의 포물선 자체는 판정에 넣지 않는다(그건 근접 위협 위에 얹히는 추가 위협일 뿐, 판정 통과의 필요조건이 아니다).
  - `dropper`: 자기 몸이 서 있는 지점 하나가 위험구간이다(`Turret`과 동일 패턴).
  - `flyer`: `Gear`가 이미 쓰는 "축+거리 왕복 위험구간" 공식을 그대로 재사용한다(공중이라 `mountSurfaceOf`는 `null` — `pendulum`/`gear`/`thwomp`와 동일 취급).
- `mountSurfaceOf()`: `hammerThrower`/`charger`/`dropper`는 실제로 지면에 서 있으므로 `hazard.y`를 표면으로 등록(= 그 좌표에 진짜 발판이 있어야 한다는 검증이 자동으로 걸림). `flyer`만 공중이라 `null`.

이 단순화로 새로운 포물선 기하 계산이 필요 없어졌다 — 기존 `Enemy`/`Turret`/`Gear`/`Cannon`/`Thwomp`의 패턴을 그대로 재사용한다.

## 오브젝트 구현 방식

| 새 클래스 | 참고한 기존 클래스 |
|---|---|
| `HammerThrower`(왕복+투척) | `Enemy`(왕복/스쿼시) + `Cannon`(타이머 발사) |
| `Hammer`(투척 발사체, 중력 적용 포물선) | `Cannonball`(그룹에 추가 후 `reapplyVelocity()`로 속도 재적용 — `Group#add`가 속도를 0으로 되돌리는 문제 우회) |
| `Flyer`(공중 왕복) | `Gear`(축+거리 왕복 수학) — 다만 즉사 대신 스톰프 가능하게 `Turret.kill()` 패턴 사용 |
| `Charger`(왕복+돌진) | `Enemy` + 신규 순수 함수 `withinRange()`(감지 판정) |
| `Dropper`(고정+낙하 발동) | `Turret`(고정 배치) + `Thwomp`(감지→예고→발동 상태기계) |
| `FallingRock`(낙하 발사체, 순수 중력) | `Cannonball`과 동일 생명주기(그룹 추가 + 지형 충돌/월드 밖 시 제거) |

신규 순수 함수 `withinRange(dx, dy, rangeX, rangeY)`(`src/objects/proximity.ts`)를 `Charger`의 돌진 감지와 `Dropper`의 낙하 감지에 공유한다. 시간/기하 로직은 순수 함수로 분리해 테스트하는 기존 관례(`motion.ts`, `patrol.ts`, `ballistics.ts`)를 따른다.

## 텍스처/수치

`BootScene`에 새 텍스처 6개(`hammerThrower`, `hammer`, `flyer`, `charger`, `dropper`, `fallingRock`) 추가 — 기존처럼 단순 도형/색상. 정확한 색은 구현 시 기존 팔레트(`COLORS`)에서 골라 붙인다. 튜닝 수치는 `config.ts`에 새 블록으로 추가하고 시작값은 기존 유사 몹(±`ENEMY`/`CANNON`/`THWOMP`)에서 가져온다.

## 스테이지 9·10 구성

기존 스테이지7(`Gauntlet`)이 5구간으로 기존 기믹을 총동원한 방식을 따른다.

**스테이지 9 — 신규 몹 첫 등장** (~7200px, 6구간): 준비 → 망치투척몹(+이동발판/컨베이어) → 공중패트롤몹(+진자/기어) → 감지돌진적(+트랩플로어/크럼블) → 수직낙하몹(+대포/터렛) → 총동원 재활용(+골).

**스테이지 10 — 최종 결전** (~7200px, 6구간): 신규 몹을 처음부터 기존 기믹과 겹쳐 배치해 밀도로 난이도를 올린다. 정확한 좌표는 구현 중 도달 가능성을 계산하며 정한다(최대 점프고 ~165px, 이동속도 260, 기존 스테이지의 관례).

## 그 외 확인된 필수 변경

- `src/levels/index.ts`의 `levels` 배열에 `level9`, `level10` 추가(이것만으로 HUD/사망화면의 "STAGE N/10" 표기가 자동 갱신됨 — `levels.length` 참조 구조 확인함).
- `src/worlds.ts`의 `WORLD_FOR_STAGE`는 8칸으로 고정되어 있어 **자동으로 늘어나지 않는다** — `"underground"` 2건을 명시적으로 추가해야 한다(안 하면 9·10이 조용히 `grassland`로 표시됨).
- `README.md`의 수동 플레이테스트 체크리스트에 있는 "STAGE N/8"·"8개 스테이지" 문구를 10으로 갱신하고, 신규 몹 4종의 스톰프/즉사/투척 확인 항목을 추가한다.

## 검증

- `npm test` — 기존 `threat.test.ts`의 "모든 스테이지" 전수 스윕이 `levels` 배열을 순회하므로, 9·10을 추가하는 순간 자동으로 위협 검증 대상에 포함된다.
- `npm run build` — 타입체크. `HazardDef` 유니온에 새 kind를 추가하면 `threat.ts`의 `never` 강제 체크 때문에 등록을 빠뜨리면 컴파일이 실패한다.
- 신규 순수 함수(`withinRange`)는 `proximity.test.ts`로 유닛테스트.

## 진행 방식에 대한 메모

사용자가 외출하며 "위 설계 내용으로 완료해달라"고 위임했다. 브레인스토밍 스킬 절차상 원래는 이 문서를 사용자가 리뷰한 뒤 계획 단계로 넘어가지만, 이번엔 그 검토 없이 곧바로 구현으로 진행한다. 구현 중 이 문서의 가정과 다른 부분(특히 위 "단순화" 절)이 생기면 이 문서를 갱신해 실제 구현과 맞춘다.
